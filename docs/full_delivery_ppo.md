# 三机城市配送算法说明（当前交付版本）

本说明对应 2026-11-22 整理的源码与已冻结模型。当前算法组合为 **OR-Tools 任务分配＋三维 A*＋PPO 三维速度局部避障＋安全约束和多机协调**。货物为可视化随飞与投递；没有质量、绳索或抓取动力学。

## 1. 分层执行

1. YAML 提供城市、取送货点、容量和规划参数；六单均衡覆盖三个收货点。
2. OR-Tools 求解带容量约束的取送货路线。约束同单先取后送、同机执行、载货量不超过容量，同一目的地唯一负责飞机，不同目的地由不同飞机负责。目标兼顾总预计航时与最大路线航时，不保证限时求解得到全局最优。
3. A* 在 1 m 体素网格上搜索 26 邻域，静态障碍膨胀 1 m；步代价和启发均基于欧氏距离。搜索后用可通视检查删减航点。每个取货、配送和返航阶段保留独立航段。
4. 无动态风险时跟踪航点；相对目标前视距离≤8 m。根据实际激光与静态地图预期回波的差异及运动方向相关性判定新增风险，风险距离<6 m时可触发 PPO。退出需要最短接管时间与连续清空条件，避免抖动。
5. PPO 输出前/左/上速度请求，随后经过高度、净空、方向、静态几何、宽点云及双方机间约束，再交由 PX4 执行。不使用势场引导。
6. 未知近障或交通风险可将实测点云表面点、等待飞机占用区域加入独立临时栅格并异步重规划 A*。不读取动态球的 Gazebo 真值作为策略观测。
7. 服务点内位置误差≤0.8 m、速度≤0.45 m/s、连续驻留2 s，且货物服务确认后才更新任务状态。三机以26/28/30 m高空航段返航，在各自起点上方下降降落。

## 2. PPO 观测与动作

观测153维：四帧36扇区激光144维、机体相对目标3维、机体速度3维、高度上下余量2维、下方净空1维。每帧激光三层垂直角为−12°、0°、12°，每层压缩为12个方向。四帧历史隐含距离变化趋势，没有 LSTM。固定特征缩放不产生避障动作。

动作 a=(a_f,a_l,a_u)，每项∈[−1,1]。先映射为 v=(2a_f,2a_l,a_u) m/s，再径向缩放使三维速度模长≤2 m/s；垂直分量绝对值≤1 m/s。机体坐标为 FLU，执行时转换为 PX4 NED。策略工作高度为2～32 m。

Actor/Critic 隐藏层配置为[128,128]。冻结模型可直接用于推理，无须重新训练。当前模型是困难强化阶段50,000步检查点，已继承前期完整高度策略权重；该数字不是从零累计训练步数。元数据见 `models/ppo_delivery/metadata.json`。

## 3. 当前配送训练奖励

设 L_t 为沿当前 A* 航段的剩余长度，d_t 为扣除0.45 m机体半径并考虑运动扫掠后的障碍净距，I为条件指示量。代码为：

```python
reward = 12 * (previous_remaining - remaining)
reward -= 0.04 + 0.005 * remaining
reward -= 5 * max(0, 1.2 - clearance) ** 2
if braked and ppo:
    reward -= 0.8
if speed < 0.15:
    reward -= 0.2
if collision or outside:
    reward -= 1000
elif success:
    reward += 150
if truncated:
    reward -= 300
```

推进项鼓励沿路前进；时间与剩余距离项减少拖延；1.2 m内的二次净距惩罚抑制贴障；安全投影后的完全制动和低速惩罚减少依赖停车；碰撞/越界强惩罚，到达本段目标给终止奖励。

到达条件为距航段终点<0.8 m且无碰撞、越界。连续两步激光最小距离<0.8 m或达到750步时截断；步长0.1 s。奖励针对单个训练航段，没有直接的整队配送奖励、取货奖励、能耗项或显式动作平滑项。多机间距通过运行时协调保证，当前没有多智能体联合PPO训练。

困难强化阶段保存参数：学习率1e−4，gamma=0.995，GAE lambda=0.95，clip=0.2，熵系数0.005；8个并行环境，每环境采样256步，batch=256，每轮8次更新。随机化障碍相位、响应时间0.3～0.55 s、加速度2～3.2 m/s²及0～2步延迟；增加出发航段和指定种子回放。训练在简化运动环境中进行，Gazebo/PX4用于闭环验证。

## 4. 动态障碍、安全与协调

默认新增8个全城球、2个出发通路球，保留原运动球。全城按四象限分层采样，中心高度7～30 m，垂直振幅0.35～1 m；按完整轨道包围范围而非初始位置检查建筑、树木和地图边界净空。出发障碍沿初段A*采样且避开起降柱。参数与种子写入 `obstacles.json`；启动时间差仍会影响实际交汇时刻。

额外11层±60°、8 m安全点云不输入原PPO网络，补充垂直盲区。速度层保留通过检查的请求分量或缩放，必要时置零；静态几何前瞻与机间约束一并执行。双方飞机都受接近速度约束，不能只要求低优先级方停车；临时A*为对方保留3.6 m占用球。共享屋顶点由先到者占用，离开后释放。

观测或遥测超过0.5 s不新鲜时等待恢复，持续中断超过2 s则全队中止降落；连续两帧激光<0.8 m也触发中止。返航保留爬升、巡航、起点下降航段边界。安全层参与次数单独记录，不能把整体结果全部归为PPO独立学会的行为。

开发过程有机间距不足、近障中止和误分类等失败，旧记录保存在本机项目外压缩归档，未回写成通过。特别是中间seed 2批次虽送完并返航，但控制最小机间距1.975 m而被判FAIL；改进双方约束后才获得表内结果。

两个布局不构成随机泛化可靠性统计。尚需更多种子、噪声和跟踪扰动测试，尚无实机和物理载荷结论。训练段指标与完整配送指标须分别陈述。
